# Koshava — контекст проекта

Этот файл — общая память проекта для людей и агентов (Claude Code читает его в начале каждой сессии). README.md описывает установку и деплой; здесь — что уже решено, почему и чему мы научились. Обновляйте его, когда меняется что-то из описанного.

См. также `AGENTS.md` (его пишет `next dev`): это Next.js 16, API отличаются от привычных — перед кодом читайте `node_modules/next/dist/docs/`.

## Что это

Интернет-магазин с доставкой продуктов из Lidl Srbija по Белграду (пилот). Весь каталог — официальный прайс-лист Lidl (~3 100 товаров), цены оттуда же. Интерфейс на русском и сербском (`/ru`, `/sr`).

- Прод: https://koshava.vercel.app (Vercel Hobby, функции во Франкфурте `fra1`).
- Репозиторий: `iscajenie/koshava`, **публичный**. Каждый push в `main` сразу деплоится.
- База: Supabase (Postgres). На Vercel `DATABASE_URL` должен быть строкой Transaction pooler (порт 6543).
- Правила магазина — `src/config/shop.ts`: заказ от 5 000 до 30 000 RSD, доставка 10 % от суммы товаров, один выезд в день (10:00), со следующего дня, оплата только наличными курьеру, зона — городские районы Белграда.

## Стек и структура

Next.js 16 (App Router, Turbopack) · React 19 · Tailwind CSS v4 · Drizzle ORM + postgres.js · zod · sharp · Vitest · Playwright.

```
src/app/[locale]/        страницы; главная = каталог; @modal — товар и корзина поверх страницы
src/app/[locale]/admin/  заказы, каталог и импорт, библиотека Lidl, Telegram
src/actions/             server actions: корзина, избранное, вход, заказ, админка, telegram
src/lib/                 каталог, корзина, заказы, форматирование, telegram, import/*
src/components/          UI (shell = сайдбар, header, product-card, overlay, …)
src/i18n/dictionaries/   ru.ts и sr.ts — все тексты интерфейса, держать в паре
src/db/schema.ts         схема; миграции в drizzle/ (drizzle-kit generate)
scripts/                 импорты и синки (запускаются в GitHub Actions)
data/                    справочные данные для фото (см. ниже)
tests/ (vitest), e2e/ (playwright)
```

## Интерфейс

- Стиль — по магазину Lidl на Everli: Fira Sans, заголовки и цены — Montserrat (у Poppins нет кириллицы). Цвета, кнопки и пилюли — токены и `@utility` в `src/app/globals.css`. Компонентные классы — только через `@utility`: обычный CSS перебивает утилиты вроде `hidden`.
- Десктоп: сайдбар 300 px (категории), шапка 68 px. Телефон: сайдбар выезжает из меню, нижнего меню нет.
- Карточка товара и корзина открываются поверх страницы: параллельный слот `@modal` + intercepting routes, нативный `<dialog>`. Переключатель языка — обычные `<a>`, чтобы перехват не срабатывал.
- Баннер на главной: высота 180 px; бейдж «Доставка 10 %» → заголовок → описание в одной колонке, справа круги цветов лого. Размеры подбираются container queries по ширине самого баннера. Условия заказа («Заказ от … · Подробнее / Оплата при получении») стоят в шапке правее поиска от `xl`; на более узких экранах — в баннере рядом с бейджем.
- У фото не с lidl.rs на карточке тег «Фото: <источник>» (cenolov, everli, lidl.de, maxi, Open Food Facts…).

## Фото товаров

На lidl.rs Lidl показывает только ~500–700 текущих предложений, поэтому фото собираются из многих источников. Порядок выбора (код — `applyLidlLibrary` в `src/lib/import/lidl-library.ts`):

1. lidl.rs по штрихкоду (`lidl`) — всегда главнее.
2. maxi.rs, online.idea.rs по штрихкоду (`maxi`, `idea`) — не пересчитываются и не заменяются.
3. Каталоги Lidl других стран по штрихкоду (`lidl-intl`), ближайшие страны первыми.
4. Проверенные вручную пары по названию с сербскими товарами: архив lidl.rs, cenoteka.rs (`lidl-name`).
5. cenolov.rs по штрихкоду (`cenolov`): упаковка сербская, но фото иногда подобрано «похожее».
6. Open Food Facts (`off`).
7. Пары по названию с Lidl Italia из Everli (`lidl-name`) — только товарам совсем без фото.

Источники 3–5 и 7 пересчитываются при каждом синке и заменяют фото Open Food Facts. Неизменённые товары не перезаписываются.

Данные:

- **Библиотека** `lidl_library` / `lidl_images`: каждый товар, когда-либо бывший на lidl.rs, с превью (WebP ≤ 600 px, в базе, отдаётся через `/api/img/<id>`). Сюда же записываются товары Lidl других стран и справочные товары (ключи `everli:…`, `cenolov:…`, `cenoteka:…`).
- `data/lidl-name-matches.json` — пары «наш source_key → ключ библиотеки», каждая проверена человеком: по названию, весу, цене и фото.
- `data/everli-lidl-it.json` — товары Lidl Italia из выгрузок Everli; фото скачиваются с CDN Everli.
- `data/cenolov-lidl-rs.json` + `data/photos/cenolov/` — ~1 100 товаров cenolov.rs со штрихкодами.
- `data/cenoteka-lidl-rs.json` + `data/photos/cenoteka/` — товары cenoteka.rs без штрихкодов, используются только через пары.
- Формат JSON в data/: ключи отсортированы, `indent=1`, `ensure_ascii=False`, без перевода строки в конце.

Сайты, закрытые от ботов (Cloudflare/WAF: cenolov, cenoteka, eponuda, Lilly, Metro), **не обходим**. Их данные попадают в проект только из HAR-выгрузок, которые владелец сохраняет в своём браузере. Фото из таких выгрузок кладутся в `data/photos` с согласия владельца (репозиторий публичный).

## Автоматика (GitHub Actions, общая группа concurrency `import`)

| Workflow | Когда | Что делает |
|---|---|---|
| `lidl-library.yml` | каждый час по будням 06:17–16:17 UTC и ночью 23:37 UTC | миграции → sitemap и поиск lidl.rs → новые страницы и фото → справочные товары → пересчёт фото |
| `lidl-abroad.yml` | вт и пт 01:13 UTC (~45 мин) | ищет штрихкоды товаров без фото / с фото OFF или cenolov на 30 сайтах Lidl |
| `idea.yml` | ср 01:43 UTC | фото online.idea.rs |
| `import.yml` | вручную (full/quick) | прайс-лист Lidl, фото OFF и maxi |
| `ci.yml` | push | lint, typecheck, тесты |

Ручной запуск: `gh api -X POST repos/iscajenie/koshava/actions/workflows/<file>/dispatches -f ref=main`.

## Уведомления о заказах

Telegram-бот настраивается в Админка → Telegram: токен от @BotFather → «Старт» в боте (или бот в группе и `/start`) → «Найти чаты» → «Подключить». Токен и чаты хранятся в таблице `settings`, закрытой RLS для Data API Supabase. Сообщение уходит через `after()` после ответа покупателю, поэтому сбой Telegram не ломает оформление. Для тестов `TELEGRAM_API_URL` направляет запросы на заглушку.

## Уроки эксплуатации

- Дважды прод отдавал 500 на всех страницах 1–2 минуты. Оба раза новый деплой совпал с синком библиотеки — скорее всего, кончались соединения с базой. Поэтому: `idle_timeout: 20` в `src/db/index.ts`, и **не запускать синки одновременно с деплоем** — сначала дождаться деплоя (статус коммита Vercel `success`), потом dispatch. Логов Vercel у агента нет: нужен коннектор Vercel или токен в настройках окружения.
- Перед выводами о проде проверять его напрямую (curl, Playwright). Не делать на проде тестовых заказов и не трогать корзину.

## Как работать в репозитории

- Коммиты небольшие, сообщение по-английски: что и почему. `git commit --amend` недоступен — только новые коммиты.
- Перед пушем: `npm run typecheck`, `npm run lint`, `npm test`, `npm run test:e2e` (e2e идут против запущенного dev-сервера на :3000; `admin@koshava.test` должен быть в `ADMIN_EMAILS`).
- Тексты интерфейса — только через словари ru/sr.
- Локально (облачный контейнер):
  - Postgres: `su postgres -c "/usr/lib/postgresql/16/bin/pg_ctl -D /var/lib/koshava-pg/data -l /var/lib/koshava-pg/log -o '-p 5432 -k /tmp' start"`.
  - Node-скриптам, которые ходят в интернет, нужен `NODE_USE_ENV_PROXY=1`.
  - Не запускать `pkill` в одной команде со строкой, совпадающей с шаблоном (`next dev`, имя скрипта): команда убьёт сама себя (exit 144).
- Секреты не просить в чат и не хранить в репозитории.
